# CLI reference

Requires Node.js 22.12.0+. Run from the repository root.

## Build / validate
| Command | Notes |
|---|---|
| `npm run build -- <site>` | Build one Site. Name may be omitted only when `sites/` has exactly one Site |
| `npm run build -- all` | Build all Sites (needed after changing a component other Sites reference; also regenerates `@/site/` path mappings) |
| `npm run typecheck` | Run AFTER the build (cross-Site `@/site/` mappings are generated by build) |
| `npm run export:react -- <site\|all>` | Export components as a React library. Only when the user asks |

A freshly cloned Site has no `component-index.json`, `page-index.json` or `tsconfig.json`: run `npm run build -- <site>` once.

## Dev servers
`npm run dev` / `npm run preview` are long-running and occupy port 3000. **Do not start them unless the user asks.** They take one Site at a time (no `all`) and must not run concurrently.

## Scaffolding (prefer over hand-creating files)
```bash
npm run create:site -- my-site [--prefix myprefix]
npm run create:component -- "My Component" --site my-site [--prefix myprefix]
npm run create:page -- "My Page" --site my-site [--prefix myprefix]
```
- Always pass `--site` when more than one Site exists.
- The `--prefix` should match the prefix in the Site's `src/styles/tailwind.css`. Read it first; omit the flag if unsure.
- After scaffolding, edit the generated content. Do not rewrite the structure. The only allowed removals are the lighter forms in `component-rules.md` (Authoring forms), and only when the user asked for them.

## Failure handling
Tell apart errors introduced by your change from pre-existing ones. Never work around a failure by editing build configuration.


## Quick checks (run before `build`)

Run from the repository root, replacing `<site>`. Each check should print nothing. Judge any hit before acting, since a match inside a comment or string is not a violation.

```bash
# 1. Browser APIs in component templates and page index.tsx (both are server-rendered)
grep -nwE "window|document|localStorage|sessionStorage|navigator" sites/<site>/src/components/*/template.tsx sites/<site>/src/pages/*/index.tsx

# 2. Page manifests must not contain an "entry" field
grep -l '"entry"' sites/<site>/src/pages/*/manifest.json

# 3. Component manifest name must equal its directory name
for d in sites/<site>/src/components/*/; do n=$(basename "$d"); grep -q "\"name\": *\"$n\"" "$d/manifest.json" || echo "name mismatch: $n"; done

# 4. Site name: directory, site.json and package.json must be identical
grep -H '"name"' sites/<site>/site.json sites/<site>/package.json

# 5. Component index.ts must be exactly the one-line default re-export
for d in sites/<site>/src/components/*/; do grep -qE "^export \{ Template as default \} from ['\"]\./template['\"];?\s*$" "$d/index.ts" && [ "$(grep -c . "$d/index.ts")" = 1 ] || echo "index.ts differs: $d"; done

# 6. Hand-written registration / mounting leftovers (automatic now)
grep -rnE "registerComponent|data-component|runtime" sites/<site>/src/components/*/index.ts sites/<site>/src/components/*/template.tsx sites/<site>/src/pages/*/index.tsx

# 7. controller.ts must export mount
for d in sites/<site>/src/components/*/; do [ -f "$d/controller.ts" ] && ! grep -qE "export (async )?(function|const) mount|export \{[^}]*\bmount\b" "$d/controller.ts" && echo "no mount export: $d"; done

# 8. examples.md code must be bare JSX: no import/export/return, no `...` placeholders
grep -nE "^\s*(import|export) |^\s*return[ (]|>\.\.\.<|^\s*\.\.\.\s*$" sites/<site>/src/components/*/examples.md
```

These do not replace the checklists in `style-rules.md`, `component-rules.md` and `page-rules.md`. They only cover what a text scan can decide.
