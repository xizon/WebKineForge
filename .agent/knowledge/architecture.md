# Architecture (project-level constraints)

## Model
- **Project** > **Site** > **Page / Component**. Each Site is an independent sandbox and builds into its own `dist/` (a standalone static Website).
- Stack: TypeScript + TSX (build-time HTML templating only) · Tailwind CSS v4 · Vanilla CSS · native interaction (GSAP / Three.js, etc.). No framework, no hydration.

## Directory map
```
sites/<site>/
├── site.json            # Site config (name, lang, title, template, paths, entries)
├── package.json         # Site dependencies + build.externals
├── site.html            # Optional HTML shell (only if site.json "template" points to it)
├── component-index.json # GENERATED by build. Never hand-edit
├── page-index.json      # GENERATED by build. Never hand-edit
├── tsconfig.json        # GENERATED by build. Never hand-edit
├── public/              # Static assets, copied to dist
├── src/
│   ├── styles/tailwind.css     # Tailwind entry, holds prefix(...)
│   ├── components/<name>/      # template.tsx, controller.ts, style.css, index.ts, manifest.json, examples.md (style.css / controller.ts optional in lighter forms, see component-rules.md)
│   └── pages/<name>/           # index.tsx, style.css, manifest.json
└── dist/                # GENERATED. Never hand-edit
```
Root-level `core/`, `runtime/`, `vite.config.ts`, root `package.json` / `tsconfig.json` are off-limits unless the user explicitly asks to change the build system.

## Layer responsibilities
| Layer | Component | Page | Runs when |
|---|---|---|---|
| Template (static HTML) | `template.tsx` | `index.tsx` default export | Build time (Node). No browser APIs |
| Controller (interaction) | `controller.ts` (exports `mount`; optional for purely static components) none (pages have no browser code) | Browser |
| Style | `style.css` (optional for components: Tailwind utilities or inline `style={{ ... }}` also work) | `style.css` | Build / CSS |
| Registration & mounting | `index.ts` (one-line default re-export; registration and mounting are automatic) | imports components in `index.tsx` (mounted automatically) | Build / server render |
| Info | `manifest.json` | `manifest.json` | Build (index, SEO) |

## Page = one file
A page's `index.tsx` is both the server and the client entry:
- It imports global styles, page styles and components, and contains the page HTML structure (component ordering).
- Components are registered and mounted automatically; the page never imports a runtime or calls a component's `mount`.
- It contains no browser code and no `typeof window` block.
- Page `manifest.json` has **no `entry` field**. Do not add one.

## Three layers: recommended default, not a hard rule
Components default to separated Template / Controller / Style. Lighter forms are allowed under the conditions in `component-rules.md` (Authoring forms). The one non-negotiable constraint is the server-side rendering rule below.

## Hard rules
- Never access `window` / `document` / `localStorage` etc. at module top level or inside a page `index.tsx` or a default-export template. The only place browser code may live is inside `controller.ts` functions. Templates run in Node at build time; browser code in a template or at its module top level throws `ReferenceError` (e.g. `document is not defined`).
- Component registration and mounting are automatic. The server injects `data-component` and the mount script, and picks up `controller.ts` (`mount`) if it exists, otherwise a no-op. Never hand-write `registerComponent`, runtime imports, `data-component` or mount scripts.
- Build-generated files are never hand-edited.
- Build/index outputs are the source of truth for what exists: use `component-index.json` / `page-index.json`.
