# Page rules

A page directory (kebab-case) in `sites/<site>/src/pages/<name>/` has **3 files**:
```
index.tsx       # Client + server entry: page HTML structure and component placement
style.css       # Page-specific styles
manifest.json   # Page info and SEO
```
Do not name a page `index` (`index.html` is generated by the build).

For complete styling, prefix, naming, escaping, and isolation rules, see **[style-rules.md](./style-rules.md)**.

## index.tsx
Single file, rendered at build time. Components are registered and mounted automatically: do not import a runtime or write any mount code. Required order:

```tsx
// Global styles
import '@/styles/tailwind.css';

// Custom styles
import './style.css';

// Components
import MyComponent1 from '@/components/my-component1';
import MyComponent2 from '@/components/my-component2';

export default function SamplePage() {
    return (
        <main>
            {`<!-- Comment Here -->`}
            <MyComponent1 />
            <MyComponent2 />
        </main>
    );
}
```

Rules:

- `@/` points to the current Site's `src/`. Cross-Site components use `@/site/<site>/components/<component>`; cross-Site static assets are imported from `@/site/<site>/assets/<file-path>` (full path with subfolders + file name, not the bare name).
- A page contains **no browser code**: no `window` / `document` access and no `typeof window` block, because `index.tsx` is server-rendered. Interaction belongs in a component's `controller.ts`.
- The default export is a PascalCase function; it returns the page body. Do not add `<html>`, `<head>` or `<body>` (the Site shell / `site.html` owns them).
- Every component used in JSX is imported; every import is used. Components imported = components placed.
- Do not put controller logic or animations directly in the page. If something needs interaction, make it a component.
- Root elements need no class by default. Add Tailwind utilities or custom classes from `style.css` only when the page needs them.

## Styling

All styling rules live in **[style-rules.md](./style-rules.md)**. Page-specific points:
- Tailwind utilities first (matching `prefix(...)` in `src/styles/tailwind.css`, if configured) for layout and spacing.
- Page-scoped custom classes go in `style.css`, using the page name as a namespace (e.g., `.wkf-samplepage-1__hero` or `.my-samplepage-1__hero`). Avoid generic names like `container`, `title`, or `custom-*`.
- Pages keep their 3-file structure; the lighter component forms (no stylesheet, no controller) do not apply to pages.

## manifest.json
| Field | Required | Notes |
|---|---|---|
| `name` | yes | Same as directory name |
| `type` | yes | Always `"page"` |
| `version` | - | |
| `output` | - | Output file name, default `{name}.html` |
| `bodyClass` | - | Space-separated class names on `<body>` (e.g., `"wkf-samplepage-1 wkf-theme-dark"` or `"samplepage-1"`). Default `"page"` |
| `seo` | - | See below |

### `bodyClass`
- Used in `style.css` to differentiate page-level themes or layouts. Use descriptive, page-scoped names (no generic names).
- Recommended to carry the Site prefix followed by a hyphen (e.g., `.wkf-samplepage-1`, no escaping needed), though unprefixed names are also permitted. Avoid colon-style names: `wkf:` is reserved for Tailwind utilities, and if one is used anyway, escape it in CSS as `.wkf\:samplepage-1`. Follow the existing convention of the Site and never mix both styles in the same Site (see **[style-rules.md](./style-rules.md)**).

**There is no `entry` field. Remove it if found in an old page.**

`seo`: `title` (required), `lang` (falls back to Site), `description`, `keywords` (string[]), `author`, `canonical`. Custom keys: `og:*` render as `<meta property>`, others (`twitter:*`, ...) as `<meta name>`.

## Links between pages
Relative link to the target's output file: `<a href="./samplepage-2.html">...</a>` (`manifest.output`, else `{name}.html`). Check the target page exists in `page-index.json`.

## Checklist
- [ ] 3 files (`index.tsx`, `style.css`, `manifest.json`), `name` matches directory (not `index`), no `entry` in manifest
- [ ] `index.tsx` order: global styles, page style, components, default export; no runtime import and no mount code
- [ ] All imported components exist (`component-index.json`) and are used; no browser APIs anywhere in the page
- [ ] Styling and `bodyClass` follow **[style-rules.md](./style-rules.md)** (Tailwind first, page namespace on custom classes, `prefix-` for custom classes and IDs, `prefix:` only for Tailwind utilities, consistent prefix usage)
- [ ] `output` does not collide with another page
